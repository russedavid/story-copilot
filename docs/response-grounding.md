# Source-grounded response review

The editing stage checks declarative world claims as well as player and rule claims across narration, direct answers, questions, requested checks, and private notes. Short assertions inside NPC dialogue are included; they cannot bypass review merely because no player name or number appears. Factual private commentary is checked too: moving an invented event into a note does not make it acceptable. A general “no issues found” verdict is insufficient when the draft contains an identified claim.

Each required claim gets one assessment. The live model returns compact claim and source-span indexes; the application resolves them to exact original quotations before running the same source, visibility and uncertainty checks. It retains the full source context and both compact and expanded assessments. This avoids making the model repeatedly copy source text or long identifiers. A supported claim needs an exact quote from a supplied source. Generated feedback and earlier drafts cannot provide that support. A numerical rule assertion needs a rule source; an unanswered question or resource record is insufficient. Explicit zero modifiers require explicit zero-valued rule evidence. An absent rule does not establish zero. Explicitly unknown evidence also cannot support a definite world claim: “nobody knows whether” is not evidence of “nobody did.” This detects a class of overconfident entailments; it is not a general natural-language proof.

For supported statements beginning with a player’s name, the application renders the wording of one verified source instead of trusting a looser paraphrase. Factual private commentary can be rendered as a labelled source quotation. This is deliberately conservative: a paraphrase must not add a gesture or feeling. The editor may remove an unnecessary player description while retaining creative NPC speech and world reactions. NPC dialogue can address a player without scripting that player’s reply, including across sentence boundaries. Consistent invented NPC dialogue is a proposal, not proof of a past event. Exact quotation still does not prove all possible implications, actor identities, or temporal interpretations; semantic evaluation remains necessary.

The stage allows at most two model calls within one 150-second deadline, with a 2,200-token output allowance accounted for in its input budget. When `STORY_MAX_CONTEXT_TOKENS` explicitly declares a larger serving window, review can expand beyond the preferred input budget to fit its complete source and claim assessments. It never exceeds that configured ceiling or drops sources to fit. A final partial repair retains verified clauses from the latest revision instead of restoring an obsolete draft. A repair that adds new consequential claims is checked again. If verification cannot finish, unverified sentences are removed while independently supported content is retained; the response is marked partial; an empty or unhelpful answer is not an evaluation success. If a bounded repair cannot preserve an explicit source uncertainty, its affected prose is replaced with relevant verified source statements in private guidance. This preserves the known facts and the unknown, without leaving adjacent invented justification in place. The trace retains the original, assessments, source-wording substitutions, repairs, uncertainty fallbacks, failures, and call accounting. Quote delimiters left orphaned by a removal are cleaned without inventing replacement text.

Factual, rules, and character-private answers use the base writer with deterministic decoding, even when a workspace selects a creative storytelling adapter. Creative narration still uses the configured adapter. Its scene-writing contract leaves the direct factual-answer slot empty, so a new scene request does not automatically acquire unrelated bookkeeping. The reviewer receives the current contribution explicitly; a verified factual fallback can still be shown when a scene draft cannot be grounded. This does not mutate the workspace configuration or affect player adapters. Model editing remains fallible: it can miss an NPC continuity error or approve a vague answer. A guarded response is not proof of useful assistance.

Replay saved response/context pairs against a configured model:

```sh
python -m story_copilot.review_regressions \
  --cases /path/to/private/cases.json --home /path/to/workspace \
  --output /path/to/new/private/review
```

The cases file is an array of objects with `id`, `context` (the exact original writer input), `answer` (the structured response), and `expect` (a source-based review criterion). A reference response is not the only valid wording. Include supported player restatements, useful NPC invention, legitimate questions, and explicit zero rules alongside negative cases to detect over-restriction. Keep new training data separate from these regression and evaluation cases.
